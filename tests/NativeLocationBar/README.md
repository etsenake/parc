# Native LocationBar compatibility service

`Engine/ParcNative/location_bar.{h,cc}` implements the non-rendering service
owned by the future native BrowserWindow. It is not the visible Parc command
loaded by this component.

The implementation targets Chromium156.0.8078.48 pinned by `Engine/source-lock.json`.
Its LocationBar interface has additional widget, geometry, popup, accessibility
and initialization queries. The absent control yields false/empty/null only for
those visual surfaces. `IsFullscreen()` queries the actual owning window;
`IsEditingOrEmpty()` queries the real OmniboxView behavior. These are explicit
current-version adaptations, not newly recovered Arc142 methods. Permission
prompts and accessible command-bar announcements must be connected separately;
a missing chip is not a permission grant or denial.

Two deliberate lifetime/safety adaptations matter:

- Chromium156's view no longer owns its controller. Members are declared so the
  view dies first and clears the edit model's view pointer, followed immediately
  by the controller/client. Construct after the owning Browser's feature
  registration and destroy before its features, Browser and Profile. A raw
  Browser reference expresses this required containment; the original weak
  pointer was not an invitation to let the client outlive its Profile.
  operation dereferences it. Parc binds the real BrowserCommandController and
  checks that it exists. It does not expose that unsafe original configuration.

## Narrow AI policy prerequisite

Set supported startup features **before** constructing any such service:
disable `HistoryEmbeddings`. The constructor checks that feature's explicit
disabled override before allocating the controller. That override also
prevents Chrome's separate country/locale launch fallback. It does not alter
the global FeatureList or install a testing controller.

On-device search suggestions are no longer excluded (Josh, November 1). Their
model arrives through the component updater, which needs no Google API key, so
`DefaultOmniboxProviders()` includes the on-device head provider here and the
browser test expects it.

At this pin, `DefaultOmniboxProviders()` still selects an inert
HistoryEmbeddingsProvider with its feature disabled. Its `Start()` exits through
the client's feature check before querying history-embedding services; the
object's presence is not falsely reported as absence. See
`components/omnibox/browser/autocomplete_classifier.cc`,
`history_embeddings_provider.cc`, and
`chrome/browser/history_embeddings/history_embeddings_utils.cc` in the pin.
This guard covers these specific paths only. Other AI-capable client entrypoints,
provider behavior, service initialization and final engine-wide exclusions still
need their integration audit; no general Google-networking removal is implied.

## Checks and remaining integration

```sh
python3 tests/NativeLocationBar/check-chromium.py /absolute/path/to/chromium/src
```

The script reads existing generated `ui.ninja` and `browser_tests.ninja` flags,
then invokes that checkout's Clang with `-fsyntax-only`. It never runs GN/Ninja,
generates headers, writes the checkout, links a test, or launches an application.
Logs and exact commands go to ignored `build/tests/native-location-bar/`.

The implementation and all three browser-test cases passed syntax-only
compilation with the pinned compiler and generated flags, including warnings
as errors. Required upstream headers were generated by their actual build
targets. The check caught and corrected an outdated test-only Profile accessor.
The November 1 on-device revision passes the same check.
**The browser tests have not yet linked or executed.**

`location_bar_browsertest.cc` contains three real Chromium browser tests for
Browser/Profile/model/active-tab identity, actual command enablement, and the
inherited edit-model plus destruction contract. They use Chromium's real
in-process browser fixture, not substitute headers or a mocked Browser. They
must be linked into the pinned `browser_tests` target with `location_bar.cc`
and this include directory, then run with
`--gtest_filter=NativeLocationBarBrowserTest.*`. No overlay/build-graph change
is part of this component handoff, and these tests have not run yet.

The final custom-window integration must also verify initialization/destruction
ordering, the same service with a non-BrowserView window, separate command UI,
permission presentation and the explicit provider policy. Constructing this
object alone establishes neither command-bar UX nor browser replacement parity.
