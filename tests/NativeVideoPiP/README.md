# Native video Picture-in-Picture



## Behavior and ownership

The real browser delegate checks capability before accepting native PiP. The native factory requires exact actual tab/Browser ownership; ordinary browsers keep their upstream route. Immersive sessions are refused before entry because this macOS presenter does not implement stereo projection. The engine passes genuine playback/capability changes to the app and routes actions to the actual controller/manager. A stale hidden window cannot close a newer global session. Window release is sent to the exact application client that created it, even if global application registration changes.

The application panel initially uses 320-point width and source aspect ratio, and has the recovered floating/nonactivating/resizable/all-spaces behavior. The same native video view survives hide/reentry. Actual native window identity, bounds, visibility and destruction feed the existing PiP security-occlusion tracker. The compositor stops and disconnects its native callback/root layer before destruction. System close can synchronously delete the controller-owned overlay; terminal callback frames access no engine members afterward.

## Integration membership

The canonical v59 integration binds the production sources to the independent engine and app, preserving the verified v58 crash/recovery integration. `//cef:libcef_static` owns `video_overlay_window.mm` and the existing native application adapter. The header-only `//cef/libcef/browser/parc_native:native_video_pip_api` owns `video_overlay_window.h` and the public `native_appkit_bridge.h`. Both Chrome callers depend on that API target, avoiding a Chrome-to-libcef dependency cycle. The implementation links inside the actual CEF framework; there is no new exported C or Objective-C class.

The engine adds direct dependencies on the real PiP/window, tab, media-session, accelerated-widget, compositor and display owners. Existing content/gfx dependencies remain. AppKit and QuartzCore are declared explicitly. The original tracker stays in `//chrome/browser/picture_in_picture:impl`, and its header remains in `:picture_in_picture`. The tracker edits are composed into the existing external-protocol patch owner rather than duplicated in a second overlay target.

`//cef/tests/parc_native_video_pip:browser_tests` and `:unit_tests` are reached from the actual Chrome browser/unit test targets. Both link `//cef:libcef_static`, because the patched Chrome entry points call the real engine implementation; a header-only dependency does not satisfy those symbols. Browser cases include `HAS_OUT_OF_PROC_TEST_RUNNER`. The test presenter is the same app source mapped into the test directory. The CEF test initialization incompatibility remains an explicit execution gate; these memberships are not evidence of a successful link or run. New targets must be generated and checked with their actual target flags before linking.

The production build script compiles `Sources/ParcEngine/VideoPiPWindow.m` into the application, imports its header through the existing facade, and links that object and QuartzCore with the independent shell. The current static-ANGLE sealing policy is preserved. AppDelegate's only PiP additions are creating/releasing methods and its retained presenter array. Other concurrent toolbar and public-header changes must be composed from exact preimages, not overwritten by the private snapshot.

The reviewed resize correction commits current size before occlusion observers, revalidates the overlay weak pointer afterward, then calls real `UpdateLayerBounds()` as the terminal operation. The integration also replaces the browser test's unnecessary restricted `Browser` header with the actual public `BrowserWindowInterface`; the changed test passes a pinned compatibility syntax recheck. Fourteen existing offline packaging checks passed against the rebased packager. Full original v2 implementation/check receipts remain bound by the integration handoff; none of these checks execute genuine media or PiP controllers.
