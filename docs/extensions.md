### Little Browser extension-menu metadata carrier

`WindowState.browserExtensions` for its original Profile and filters enabled
nil-icon entries and carries the extension ID, name and image. Neither filter
requires a toolbar action. Click and context-menu actions carry the original
ID; the downstream behavior for an extension without an action remains open.

Parc's `enabledExtensions(for:)` snapshots the same user-visible Chromium
registry used by the availability carrier, including no-action extensions.
Registry order and the settings-visibility predicate are adaptations, since the
original array's ordering and membership are not established. Chromium's
ImageLoader reads manifest artwork asynchronously at 32 logical points with
available scale representations, preferring the nearest larger resource and
falling back to a smaller one if necessary. A missing, failed or still-pending image stays
nil; unlike ExtensionIconManager, this carrier does not invent its default
image completion is accepted only for the original selected page, live document
and exact enabled extension identity, and signals the existing coalesced change
callback. Snapshots retain an opaque original Browser, tab, document, generation
and extension identity; navigation, selection, registry change and shutdown
retire old values. The owner rejects security-modal dispatch and uses Chromium's
actual current action model for that exact ID. It returns false when no such
model exists, including private windows without incognito access; this refusal
is an explicit adaptation pending the original downstream contract. It does not
grant private access. The menu owner must re-query on changes, omit nil-icon
rows and separately preserve the availability boolean. Existing extension-action
browser-test source covers no-action metadata, stale values, security admission
and absence of a fabricated manifest icon; it was syntax checked only and was
not executed. The engine overlay still requires its dedicated owner's build.
